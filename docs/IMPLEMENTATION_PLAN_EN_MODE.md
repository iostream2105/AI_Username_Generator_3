# 多模式命名实施方案（含寓意/风格重构）

## 1. 目标与范围

### 1.1 本次目标
- 保留并重构“寓意”“风格”选项，降低语义重叠与理解成本。
- 新增“生成英文名字”“生成中英混合名字”两种模式（与中文模式并存）。
- 保持现有主链路稳定：首页 -> 生成 -> 结果 -> 收藏/反馈/埋点。

### 1.2 本次不做
- 暂不改后台管理端筛选维度（先通过事件 properties 记录模式）。
- 暂不改数据库表结构（优先零迁移上线）。

---

## 2. 产品方案（本次落地口径）

## 2.1 生成模式
- 新增模式字段：`nameMode`
- 可选值（本次）：
  - `cn`：中文网名（默认）
  - `en`：英文名字（新增）
  - `mix`：中英混合名字（新增）

前端交互建议：
- 首页关键词输入区上方增加模式切换（分段按钮）。
- 默认选中 `中文网名`，切换 `英文名字/中英混合` 后文案、示例、提示随模式变化。

## 2.2 寓意选项（4个，跨模式共用）
统一用于 `cn/en/mix`：
- `向上蜕变`
- `内心安定`
- `自由探索`
- `温暖联结`

设计原则：
- 寓意只表达“想传达的内核”，不承担语言风格描述。
- 避免抽象近义项并列（如“坚定/清醒”重叠）。

## 2.3 风格选项（按模式动态展示，统一中文描述）
为保证用户理解成本低，风格标签统一用中文展示；后端再映射为对应模式提示词。

- `cn` 风格：
  - `诗意文艺`
  - `现代简洁`
  - `古风雅致`
  - `梦幻灵动`

- `en` 风格：
  - `现代简洁（国际感）`
  - `柔和诗意（英文感）`
  - `个性锋利（酷感）`
  - `复古经典（旧电影感）`

- `mix` 风格：
  - `中英平衡`
  - `中文主导（英文点缀）`
  - `英文主导（中文点缀）`
  - `潮流辨识（社交ID感）`

说明：
- UI 仍保持“单选、可不选”。
- 风格作为软约束，不与关键词抢主导权。

## 3. 技术实现方案

## 3.1 前端改造

涉及文件：
- `src/App.tsx`
- `src/types.ts`
- `src/services/ai.ts`

改造点：
1. 类型扩展
   - `GenerateParams` 增加 `nameMode?: 'cn' | 'en' | 'mix'`。
2. 状态与交互
   - 新增页面状态：`nameMode`（默认 `cn`）。
   - 模式切换时重置不兼容的风格值（例如从 `cn` 切到 `en/mix`）。
3. 选项配置
   - 替换寓意列表为 4 项固定集合。
   - 风格列表按 `nameMode` 动态渲染。
4. 请求参数
   - `/api/generate` 请求体透传 `nameMode`。
5. 埋点
   - 前端 `fireTrack` 的 `properties` 增加 `name_mode`。
   - 涉及事件：`click_generate` / `click_regenerate` / `generate_success` / `click_copy` / `click_favorite` 等（至少保证关键转化事件）。
6. 文案适配
   - `en` 模式下输入提示改为“支持英文词、缩写、生日月份等”。
   - `mix` 模式下输入提示改为“支持中文词 + 英文词/缩写组合”。
   - 示例卡片按 `cn/en/mix` 动态切换。

## 3.2 后端改造

涉及文件：
- `server/index.ts`

改造点：
1. 入参扩展
   - `GenerateBody` 增加 `nameMode?: 'cn' | 'en' | 'mix'`，默认 `cn`。
2. Prompt 分流
   - 按 `nameMode` 选择不同 prompt 模板：
     - `cn`：延续当前中文命名策略。
     - `en`：明确英文命名规则（自然、可读、避免生硬拼接）。
     - `mix`：明确中英融合规则（可读、顺口、不机械拼接）。
3. 英文输出约束（在 prompt 中声明）
   - 名字长度适中（建议 1-2 个词）。
   - 尽量使用自然英文词形，不返回拼音风英文。
   - `style_tags` 使用前端展示的中文风格标签（可附加括号说明）。
4. 质量策略（核心）
   - 标签作为软约束，不强制逐项硬融合。
   - 当用户输入复杂（如 3 关键词 + 寓意 + 风格）时，自动下调风格权重，优先保证关键词与寓意。
   - Prompt 明确优先级：`关键词 > 寓意 > 风格`。
   - 结果解释中强制体现“本次优先融合了什么”（写入 `meaning_desc`，不新增字段）。
5. 事件属性
   - 生成链路写库时，在 `generate_success` 事件 `properties` 中加入 `name_mode`。
   - 可选：`click_generate` 事件也附带 `name_mode` 到 `properties`。
6. 兼容性
   - 现有 JSON Schema 不变（仍返回 `items` 结构）。
   - 失败/重试逻辑复用原流程。

## 3.3 数据与后台

涉及文件：
- `sql/analytics_tracking_design.md`（文档更新）

策略：
- 本次不改表结构。
- 使用 `analytics_event_log.properties.name_mode` 承载模式信息。
- 后台管理端本期不加筛选 UI，后续可增量支持。

## 4. 质量与验证

## 4.1 基础验证
- `npm run lint`
- 前后端本地联调：
  - `npm run server`
  - `npm run dev`

## 4.2 主链路回归（必须）
1. 中文模式：
   - 不选寓意/风格可成功生成。
   - 选择寓意/风格可成功生成。
2. 英文模式：
   - 不选寓意/风格可成功生成英文名。
   - 选择寓意/风格可成功生成且风格可感知。
3. 中英混合模式：
   - 可生成中英混合结果且读起来不割裂。
   - 复杂输入场景下可观察到“关键词/寓意优先，风格降权”。
4. 结果页：
   - 复制/收藏/换一批正常。
5. 收藏页：
   - 收藏增删查正常。
6. 反馈：
   - 满意度与意见反馈正常。

## 4.3 接口与状态码验证
- `/api/generate`：200/400/500/503 路径可复现
- `/api/track`：200/400/500/503
- `/api/favorites`：GET/POST/DELETE 成功与异常路径
- `/api/feedback`：成功与参数校验失败路径

## 4.4 结果质量抽样
- 各模式抽样至少 20 组输入：
  - 简单输入（缩写+月份）
  - 复杂输入（3关键词+寓意+风格）
- 人工标注维度：
  - 自然度
  - 融合度
  - 可记忆性
  - 与输入一致性

## 5. 发布与回滚

## 5.1 发布策略
- 小流量先发（朋友圈/种子用户）验证 2-3 天。
- 重点观察：
  - 英文模式点击生成率
  - 中英混合模式点击生成率
  - 复制率/收藏率
  - 不满意反馈率

## 5.2 回滚策略
- 前端模式开关可通过快速回退代码恢复为仅 `cn`。
- 后端保留 `nameMode` 默认兜底到 `cn`，即使前端传空也不影响旧链路。
- 因无 DB 迁移，本次回滚无数据结构风险。

## 7. 验收标准（DoD）

- 用户可在首页明确切换“中文网名 / 英文名字 / 中英混合”。
- 寓意固定 4 个、风格各模式 4 个且统一中文描述，选项语义清晰、无明显重叠。
- 英文模式可稳定输出 3 个英文候选及解释，不出现大面积中式直译僵硬结果。
- 中英混合模式可输出自然、可读、非机械拼接的候选。
- 复杂输入场景下，结果解释可体现“本次优先融合了什么”，且生成自然度不明显下降。
- 现有中文模式体验不回退。
- 核心埋点可区分 `name_mode`，便于后续比较模式表现。
- `npm run lint` 通过。
