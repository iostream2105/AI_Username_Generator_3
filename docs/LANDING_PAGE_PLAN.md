# 名有意高意图场景页规划（第一批）

## 1. 目标

高意图场景页的目标，不是单纯把首页复制 4 份，而是让不同搜索词进来的用户在首屏就看到“这页就是为我写的”。

第一批场景页优先解决三件事：

1. 承接高意图搜索词和内容回搜流量。
2. 让首屏文案、默认模式、示例结果和 FAQ 与场景匹配。
3. 用一套模板 + 配置驱动的方式落地，避免后续 4 页、8 页、12 页都重复开发。

---

## 2. 第一批 URL 规划

建议先只做 4 个高意图场景页：

| 页面 | URL | 默认模式 | 目标词方向 |
| --- | --- | --- | --- |
| 微信昵称页 | `/wechat-nickname` | `cn` | 微信昵称、微信昵称生成器、有寓意的微信昵称 |
| 小红书昵称页 | `/xiaohongshu-nickname` | `mix` | 小红书昵称、小红书名字、主页昵称 |
| 英文昵称页 | `/english-nickname` | `en` | 英文网名、英文昵称、高级感英文名 |
| 游戏 ID 页 | `/game-id` | `cn` | 游戏ID、游戏昵称、不撞名游戏名字 |

说明：

- 首页 `/` 继续保留为通用承接页。
- `/admin` 仍然保持后台入口，不纳入场景页体系。

---

## 3. 信息架构

每个场景页建议统一为同一套信息结构：

1. SEO Meta
2. 首屏 Hero
3. 输入区
4. 结果示例区
5. 场景说明区
6. 核心价值区
7. FAQ 区

### 3.1 首屏 Hero 必须包含的元素

- 场景化标题
- 场景化副标题
- 默认更贴合该场景的生成模式
- 输入框和生成按钮
- 与该场景匹配的结果示例

### 3.2 每个场景页首屏内容建议

#### `/wechat-nickname`

- 标题：想换一个更像你的微信昵称，可以先把缩写、生日和情绪输进去。
- 副标题：强调“低调耐看、熟人社交、长期可用”。
- 默认模式：中文。
- 首屏结果风格：温润、清冷、沉静、耐看。

#### `/xiaohongshu-nickname`

- 标题：想要一个更有辨识度的主页名字，先从小红书昵称开始。
- 副标题：强调“主页展示、人设号、内容账号、辨识度”。
- 默认模式：中英混合。
- 首屏结果风格：小众高级、氛围感、适合主页。

#### `/english-nickname`

- 标题：想找一个高级感英文昵称，不用再翻英文名大全了。
- 副标题：强调“社媒主页、英文人设、小众英文名”。
- 默认模式：英文。
- 首屏结果风格：意象感、氛围感、低模板化。

#### `/game-id`

- 标题：游戏 ID 不想撞名，可以先把个人线索输进去。
- 副标题：强调“不撞名、有记忆点、不过度中二”。
- 默认模式：中文。
- 首屏结果风格：辨识度、画面感、圈层气质。

## 4. 配置层设计

这次建议用一份配置驱动场景页，而不是为每个 URL 单独写一套页面。

### 4.1 配置字段

每个场景页配置建议至少包含：

- `key`
- `path`
- `analyticsPageName`
- `defaultNameMode`
- `meta.title`
- `meta.description`
- `meta.keywords`
- `meta.canonicalPath`
- `hero.eyebrow`
- `hero.titleLines`
- `hero.description`
- `sceneSection.title`
- `sceneSection.description`
- `sceneSection.scenes`
- `valuePropsTitle`
- `valueProps`
- `faqTitle`
- `faqItems`
- `modeExamples`

### 4.2 为什么要先做配置层

1. 后续新增 `/qq-nickname`、`/couple-name`、`/douyin-nickname` 时，不需要复制整页代码。
2. SEO Meta 能按路径单独设置。
3. 默认模式、首屏文案、示例结果都能按场景做差异化。
4. 便于后续做内容页和场景页批量扩展。

## 5. 本次代码落地范围

这一轮建议先做基础层，不急着一次做完所有场景页视觉差异：

1. 新增 `src/landingPages.ts`
2. 在 `src/main.tsx` 中按 pathname 解析场景页配置
3. 让 `title / description / keywords / canonical / og / twitter` 跟着路径变化
4. 让 `src/App.tsx` 首页首屏文案、场景标签、价值点、FAQ、默认模式支持配置驱动

---

## 6. 下一步实施顺序

完成这一轮基础层后，建议下一步按下面顺序推进：

1. 优先上线 `/wechat-nickname` 和 `/english-nickname`
2. 再补 `/xiaohongshu-nickname` 和 `/game-id`
3. 验证搜索和内容回搜流量是否能稳定进入场景页
4. 再扩展下一批长尾页

---

## 7. 验收重点

完成基础层后，至少要验证：

1. 访问不同路径时，首屏标题是否切换正确
2. 不同路径的默认模式是否正确
3. 页面 `title / description / canonical` 是否正确更新
4. FAQ、价值点、场景标签是否按页面切换
5. CloudBase 静态托管下，子路径能否正确回落到前端页面
